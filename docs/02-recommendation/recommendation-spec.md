# 추천 기준

[문서 허브](../README.md) · [PRD](../00-product/prd.md) · [평가 계획](evaluation-plan.md) · [후속 LLM 계약](../03-contracts/llm-contracts.md) · [데이터 설계](../05-data/data-design.md)

이 문서는 현재 로컬 MVP의 후보, 제외, FTS5 검색, 결정론적 순서와 결과 구성의 유일한 계산 기준이다. 화면 문구는 [화면 상태와 카피](../01-experience/ux-states-and-copy.md), 필드·테이블은 [데이터 설계](../05-data/data-design.md)가 책임진다.

## 1. 목표와 경계

추천 엔진은 구조화 검색 조건과 검수된 로컬 데이터만 사용해 재현 가능한 결과를 만든다.

- 후보·제외·필터·순서·동점은 TypeScript의 결정론적 함수로 계산한다.
- FTS5는 비식별 리뷰와 검수된 검색 필드만 조회한다.
- OpenAI, 외부 검색과 raw 리뷰 원문은 현재 후보나 순위를 바꾸지 않는다.
- 계정의 과거 검색·즐겨찾기를 개인화 점수로 사용하지 않는다.
- 의료·알레르기 상태를 필터·관련도·안전 판정에 사용하지 않는다.
- 사용자에게 숫자형 관련도나 총점을 표시하지 않는다.

## 2. 추천 단위와 포함 정책

추천 단위는 `store_id`가 가리키는 실제 매장이다. 브랜드 설명은 `bakery_id`, 지도·즐겨찾기·선택 기록은 `store_id`를 사용한다.

후보는 다음 조건을 모두 만족해야 한다.

1. 서울특별시 안의 고정 영업장이다.
2. 공공 원장 상태가 영업 중이며 마지막 성공 동기화가 30일 이내다.
3. 정규화 주소와 자체 좌표가 유효하다.
4. `InclusionStatus.INCLUDED`로 관리자 또는 승인된 자동 규칙의 검수를 통과했다.
5. 독립 단일점 또는 서울 영업점 2~5개를 모두 직영하는 검수된 소규모 브랜드다.
6. 리뷰 근거가 부족해도 위 조건과 현재 검색 조건을 통과한다.

공정위 자료에 없다는 사실만으로 독립점을 증명하지 않는다. 소규모 직영 브랜드는 공정위 가맹 증거 없음, 공식 채널의 운영 주체 근거, 서울 영업점 수 2~5개와 관리자 검수를 모두 만족해야 한다.

## 3. 항상 제외하는 대상

- 가맹 프랜차이즈와 프랜차이즈 의심 미검수 매장
- 서울 영업점 6개 이상의 브랜드
- 팝업, 행사 부스, 배달 전용, 공유주방, 베이커리 판매가 부수적인 일반 음식점
- 폐업·휴업·영업정지·인허가 비활성·상태 불명 매장
- 중복 병합 중, 데이터 오류, 관리자 차단, 좌표 무효 매장
- 마지막 원장 성공 동기화가 30일을 넘은 매장

서울 범위, 독립성, 영업 상태와 관리자 차단은 결과가 0개여도 완화하지 않는다.

## 4. 현재 입력 계약

추천 함수는 UI와 조회 API가 검증한 `StructuredSearchInput`을 받는다.

```text
StructuredSearchInput
├─ region
├─ storeName
├─ menuName
├─ categories
├─ openNow
├─ origin
├─ maxDistanceM
├─ reviewEvidenceStatus
├─ sortMode
├─ dataSnapshotVersion
└─ recommendationVersion
```

| 필드 | 규칙 |
|---|---|
| `region` | 정규화된 서울 구·동·역 또는 `null` |
| `storeName` | 정규화된 매장명 검색어 또는 `null` |
| `menuName` | 정규화된 메뉴명 검색어 또는 `null` |
| `categories` | 검수된 enum과 `include`/`exclude` mode의 배열 |
| `openNow` | 현재 영업 중 필터 여부 |
| `origin` | 거리 계산에 쓰는 요청 한정 좌표 또는 선택 지역 중심 |
| `maxDistanceM` | 양의 정수 거리 상한 또는 `null` |
| `reviewEvidenceStatus` | `ANY`, `AVAILABLE`, `INSUFFICIENT` |
| `sortMode` | `RELEVANCE`, `DISTANCE` |
| `dataSnapshotVersion` | 게시된 app 데이터 snapshot |
| `recommendationVersion` | 정렬·동점 규칙 버전 |

`origin`의 정확 좌표는 요청 메모리에서만 사용한다. DB·검색/선택 기록·로그·분석 이벤트·응답 payload에 직렬화하지 않는다.

## 5. 처리 순서

1. 입력 enum·범위·문자열 길이와 버전을 검증한다.
2. `INCLUDED`, 서울, 영업 중, 유효 주소·좌표인 후보를 `app.sqlite`에서 조회한다.
3. 지역과 매장명 조건을 적용한다.
4. 명시된 category `exclude`와 정책상 강한 제외를 선필터한다.
5. `openNow`와 `maxDistanceM`을 적용한다.
6. 메뉴명·category 일치를 계산한다.
7. 비식별 리뷰 FTS5 결과와 근거 상태를 결합한다.
8. 리뷰·데이터 최신성과 완성도를 계산한다.
9. 승인된 정렬과 안정 동점 규칙을 적용한다.
10. 지도와 목록에 같은 전체 후보 집합을 반환한다.

Kakao Local, OpenAI, raw 리뷰 원문과 웹 검색은 후보를 추가하지 않는다.

## 6. 강한 제외 선필터

강한 제외는 FTS5 관련도, 리뷰 수, 별점과 데이터 완성도보다 먼저 적용한다.

### 적용 대상

- 사용자 UI에서 `exclude`로 지정한 검수 category
- 정책상 제외 매장과 관리자 차단
- 비적격 브랜드·영업 상태·지역
- 메뉴·매장 자체 ID에 대한 명시적 차단 목록

### 판정

- 검수된 메뉴 또는 매장 category가 제외 대상과 일치하면 제거한다.
- 정보가 없다는 이유로 제외 특징이 `없음`이라고 추정하지 않는다.
- 제외 결과는 `filter_reason_code`와 단계별 수로 추적한다.
- 제외된 후보는 FTS 관련도나 별점이 높아도 되돌릴 수 없다.

의료·알레르기 표현은 강한 제외 입력으로 받지 않는다. 실제 재료 부재와 교차접촉 안전성을 검증할 수 없다는 안내를 제공한다.

## 7. 검색 일치와 FTS5

### 명시 필드

- `storeName`은 정규화 이름과 승인된 alias를 비교한다.
- `menuName`은 활성·검수 메뉴 이름과 alias를 비교한다.
- `categories`는 검수된 메뉴 category가 매장 집계 특징보다 우선한다.
- 사용자가 지정하지 않은 필드를 임의로 채우지 않는다.

### 리뷰 FTS5

- 비식별 처리에 성공해 `app.sqlite`에 게시된 최근 12개월 리뷰만 색인한다.
- 검색 snippet은 허용된 비식별 본문에서만 만든다.
- FTS score는 현재 query 안의 상대 순서에만 사용하고 사용자에게 공개하지 않는다.
- FTS table 오류나 불일치가 있으면 리뷰 관련도와 snippet을 제거하고 메뉴·category·지역 조건으로 대체한다.
- raw 본문, 닉네임, fingerprint와 암호화 metadata는 검색하지 않는다.

## 8. 현재 정렬 순서

모든 후보는 다음 비교 키를 순서대로 사용한다.

1. 명시 메뉴·category 일치
2. 비식별 리뷰 FTS 관련도
3. 유효 리뷰 수와 최신성
4. 영업·거리 등 방문 조건
5. 데이터 최신성과 완성도
6. 전체 평균으로 보정한 별점
7. `store_id` 오름차순

`sortMode`는 4번 방문 조건 안의 우선 키를 바꾼다.

- `RELEVANCE`: 메뉴·category·FTS를 유지하고 그다음 영업 적합, 거리 오름차순을 비교한다.
- `DISTANCE`: 명시 메뉴·category 일치를 유지한 뒤 유효 거리 오름차순을 방문 조건의 첫 키로 둔다.

어느 mode에서도 강한 제외와 명시 메뉴·category 일치를 별점이 역전하지 못한다. 마지막 동점은 항상 `store_id`로 끝낸다.

## 9. 리뷰 근거와 최신성

리뷰는 Kakao Map의 최근 12개월·매장당 최대 20개만 사용한다.

- 서로 다른 유효 리뷰 3개 이상이면 `AVAILABLE`이다.
- 0~2개면 `INSUFFICIENT`이며 후보에서 제거하지 않는다.
- 최신성은 게시일 기준으로 계산하고 오래된 근거를 최신 사실처럼 표시하지 않는다.
- 별점은 1~5번 비교 키가 같은 경우의 마지막 보조값이다.

보정 별점은 리뷰 수가 적은 매장의 극단값이 순위를 지배하지 않도록 전체 평균을 사전값으로 사용하는 결정론적 Bayesian mean이다. 공식과 prior version은 `recommendationVersion`에 고정한다.

## 10. 리뷰 부족 대체

리뷰가 3개 미만이거나 FTS5를 사용할 수 없는 후보는 다음 근거를 사용한다.

1. 적격성·강한 제외·영업·거리 통과
2. 검수된 실제 메뉴·category 일치
3. 영업 상태와 거리
4. 원장·메뉴·검수 데이터 최신성·완성도
5. 보정 별점
6. `store_id`

안내 의미:

> 최근 리뷰 근거가 부족해 확인된 메뉴와 방문 조건을 중심으로 표시합니다.

가짜 리뷰 근거, 가짜 snippet과 리뷰 수 추정을 만들지 않는다.

## 11. 결과 계약

각 후보는 최소한 다음 공개 정보를 가진다.

- `storeId`, 매장명, 정규화 주소와 지도 좌표
- 대표 메뉴·category와 근거 ID
- 현재 영업 상태 또는 확인 필요 상태
- 정확 좌표를 포함하지 않는 거리 표시
- 리뷰 근거 상태, 비식별 snippet과 기준일
- 데이터 최신성과 주의점

내부 FTS score, 보정 별점, 단계별 비교 key와 총점은 공개 응답에 포함하지 않는다. 서버는 회귀·감사를 위해 추천 버전, snapshot, filter reason과 근거 ID를 보존할 수 있다.

## 12. 지도와 목록

- 지도와 목록은 같은 `store_id` 집합을 사용한다.
- 목록 첫 화면은 상위 5개를 강조하되 전체 적격 후보를 탐색할 수 있다.
- 지도 marker 선택과 목록 선택은 같은 매장 상세로 연결한다.
- 지도 실패는 후보·순서를 바꾸지 않고 목록·주소·거리와 상세를 유지한다.
- 실제 후보가 적어도 지역·강한 제외·정책 경계를 자동 확대하지 않는다.

## 13. 빈 결과와 완화

단계별 제거 수를 기록하고 다음 완화만 사용자가 선택하도록 제안한다.

1. 지역 또는 거리 범위를 한 단계 확대
2. 현재 영업 중 필터 해제
3. 리뷰 근거 부족 후보 포함
4. 명시된 인접 category까지 보기

강한 제외, 프랜차이즈·폐업·서울 범위와 관리자 차단은 자동 또는 문구로 완화하지 않는다.

## 14. 결정성과 버전

추천 실행은 다음을 기록한다.

- `recommendationVersion`
- `dataSnapshotVersion`
- `ftsIndexVersion`
- category·alias version
- 보정 별점 prior version

API가 입력 정규화와 함께 고정한 `requestTime` context는 Asia/Seoul로 해석하고 테스트에서는 fixture로 고정한다. 모든 비교는 `null` 순서, 문자열 정규화, 반올림 지점과 마지막 ID 동점을 명시한다. 동일 `StructuredSearchInput`, snapshot과 버전이면 100회 실행에서 같은 `store_id` 순서가 나와야 한다.

## 15. 안전 고지

모든 결과 화면의 의미는 다음과 같아야 한다.

> 빵찾깅은 빵집을 추천하는 서비스입니다. 재료·알레르기·교차접촉 정보는 검증하지 않으며 안전을 보장하지 않습니다. 주문하거나 방문하기 전에 매장에 직접 확인해 주세요.

의료 관련 표현은 필터 이유, 순위, 추천 근거와 분석 이벤트에 사용하지 않는다.

## 16. 후속 챗봇 adapter

`ConversationIntentV2`, 멀티턴 patch와 LLM 설명은 후속 독립 Feature다.

- 후속 adapter는 자연어 상태를 검증된 `StructuredSearchInput`으로 변환한다.
- adapter가 만든 제외·수정은 현재 입력 schema와 같은 validator를 통과해야 한다.
- LLM은 후보·정렬·동점과 매장 사실을 생성하지 않는다.
- 생성형 설명 실패는 결과 순서와 근거 ID를 바꾸지 않는다.
- model·prompt·비용·개인정보 전송은 연결 전에 다시 승인한다.
