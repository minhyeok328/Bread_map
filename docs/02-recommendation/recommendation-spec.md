# 추천 기준

[문서 허브](../README.md) · [PRD](../00-product/prd.md) · [평가 계획](evaluation-plan.md) · [LLM 계약](../03-contracts/llm-contracts.md) · [데이터 설계](../05-data/data-design.md)

이 문서는 추천 후보, 제외, 내부 관련도, 정렬과 결과 구성의 유일한 계산 기준이다. 화면 문구는 [화면 상태와 카피](../01-experience/ux-states-and-copy.md), 필드·테이블은 [데이터 설계](../05-data/data-design.md)가 책임진다.

## 1. 목표와 경계

추천 엔진은 현재 대화의 구조화된 조건과 검수된 자체 데이터만 사용해 재현 가능한 결과를 만든다.

- 후보·제외·관련도·정렬·동점은 TypeScript의 순수 함수로 계산한다.
- LLM, 외부 검색과 리뷰 원문은 후보나 순위를 직접 바꾸지 않는다.
- Kakao 경로 API는 적격 후보의 이동시간과 경로 대안을 계산한다.
- 계정 전체 장기 취향이나 다른 대화의 피드백을 순위에 사용하지 않는다.
- 의료·알레르기 상태를 필터·관련도·안전 판정에 사용하지 않는다.
- 사용자에게 숫자형 관련도·100점 총점을 표시하지 않는다.

## 2. 추천 단위와 포함 정책

추천 단위는 `store_id`가 가리키는 실제 매장이다. 브랜드 설명은 `bakery_id`, 즐겨찾기·경로·추천 결과는 `store_id`를 사용한다.

후보는 다음 조건을 모두 만족해야 한다.

1. 서울특별시 안의 고정 영업장이다.
2. 공공 원장 상태가 영업 중이며 마지막 성공 동기화가 30일 이내다.
3. 자체 좌표와 정규화 주소가 유효하다.
4. `InclusionStatus.INCLUDED`로 관리자 또는 승인된 자동 규칙의 검수를 통과했다.
5. 독립 단일점 또는 서울 영업점 2~5개를 모두 직영하는 검수된 소규모 브랜드다.
6. 리뷰 근거의 존재 여부와 무관하게 위 조건을 통과한다. 메뉴·특징 근거가 부족하면 대체 추천 모드와 근거 부족 안내를 사용한다.

공정위 자료에 없다는 사실만으로 독립점을 증명하지 않는다. 소규모 직영 브랜드는 공정위 가맹 증거 없음, 공식 채널의 운영 주체 근거, 서울 영업점 수 2~5개와 관리자 검수를 모두 만족해야 한다.

## 3. 항상 제외하는 대상

- 가맹 프랜차이즈와 프랜차이즈 의심 미검수 매장
- 서울 영업점 6개 이상의 브랜드
- 팝업, 행사 부스, 배달 전용, 공유주방, 베이커리 판매가 부수적인 일반 음식점
- 폐업·휴업·영업정지·인허가 비활성·상태 불명 매장
- 중복 병합 중, 데이터 오류, 관리자 차단, 좌표 무효 매장
- 마지막 원장 성공 동기화가 30일을 넘은 매장

서울 범위, 독립성, 영업 상태와 관리자 차단은 결과가 0개여도 완화하지 않는다.

## 4. 입력 계약

추천 함수는 [LLM 계약](../03-contracts/llm-contracts.md)의 `ConversationIntentV2`를 검증한 뒤 다음 입력을 받는다.

```text
RecommendationInput
├─ wanted                 현재 대화에서 원하는 카테고리·축·태그
├─ avoided                완전 제외는 아닌 낮은 선호
├─ hardExcluded           재료·카테고리·태그·store_id의 강한 제외
├─ visitContext           출발지·최대 범위·시각·예산·방문 목적
├─ resultControls         이동시간순/관련도순, 현재 대화 제외 결과
├─ dataSnapshotVersion
├─ recommendationVersion
└─ requestTime            Asia/Seoul 해석 기준
```

정확한 `originLat`, `originLng`는 요청 메모리의 별도 매개변수이며 스냅숏에 직렬화하지 않는다.

## 5. 후보 생성 순서

1. `INCLUDED`, 서울, 영업 중, 유효 좌표인 매장을 자체 DB에서 조회한다.
2. 출발지를 둘러싼 경계 상자로 1차 축소한다.
3. Haversine 직선거리로 사용자가 확정한 최대 범위 안의 매장을 남긴다.
4. 검수된 메뉴 특징, 매장 집계 특징, 최근 12개월 리뷰 집계와 근거 충족 여부를 불러온다.
5. 강한 제외를 적용한다.
6. 영업시각·예산 등 사용자가 명시한 하드 방문 조건을 적용한다.
7. 각 매장의 대표 매칭 메뉴와 내부 관련도를 계산한다.
8. 적격 후보에 Kakao 경로 시간을 요청한다.
9. 선택한 정렬, 동점과 다양성 규칙으로 목록을 만든다.

Kakao Local, OpenAI, 리뷰 원문과 웹 검색은 1~7단계의 후보를 추가하지 않는다.

## 6. 강한 제외 선필터

`hardExcluded`는 임베딩, 축 유사도와 내부 관련도 계산 전에 적용한다.

### 적용 대상

- 카테고리: `CROISSANT_DANISH` 등
- 풍미·재료 태그: `CHOCOLATE`, `NUTTY` 등
- 명시 재료: `ALCOHOL`, `PORK` 등
- 메뉴·매장 자체 ID

### 판정

- 후보의 검수된 메뉴 또는 특징에 제외 대상이 명시되면 제거한다.
- 정보가 없다는 이유로 `없음`을 추정하지 않는다.
- 사용자가 `초콜릿은 이제 괜찮아`처럼 명시적으로 철회하면 현재 대화의 제외 상태에서 제거한 뒤 다시 계산한다.
- 제외된 항목은 유사도나 LLM 설명이 높더라도 되돌릴 수 없다.
- 강한 제외 결과는 `filter_reason_code`와 단계별 개수로 추적한다.

`avoided`는 후보를 제거하지 않고 취향 일치 계산에서 감점한다. 강도가 모호하면 추천 전에 `완전히 제외할까요, 우선순위만 낮출까요?`라고 확인한다.

## 7. 방문 하드 조건

강한 제외 다음에 아래 순서로 적용한다.

1. **최대 거리:** 확정한 직선거리 상한 밖 후보 제거
2. **영업시각:** `openAtIsHard=true`이면 검수된 영업시간으로 방문 시각 영업을 확인하지 못한 후보 제거
3. **예산:** `budgetIsHard=true`이면 검수된 대표 메뉴가 예산을 넘거나 가격을 확인할 수 없는 후보 제거
4. **사용자 결과 제외:** 현재 대화에서 제외한 `store_id` 제거

의료·알레르기 상태는 이 목록에 없다. 서비스는 재료 부재와 교차접촉 안전성을 검증하지 않으며 결과에 직접 확인 고지를 붙인다.

## 8. 특징 축

### 카테고리

`SOURDOUGH`, `BAGUETTE`, `CIABATTA_FOCACCIA`, `BAGEL`, `SANDWICH`, `CROISSANT_DANISH`, `BRIOCHE`, `SHOKUPAN`, `SAVORY_BREAD`, `SWEET_BREAD`, `DONUT_FRIED`, `CAKE_TART_COOKIE`, `OTHER`

### 식감 0~4

- `crustiness`: 껍질의 바삭함·단단함
- `chewiness`: 씹는 탄력
- `moisture`: 속의 촉촉함
- `airiness`: 기공이 크고 가벼운 정도
- `flakiness`: 결이 겹겹이 부서지는 정도

### 맛 0~4

- `sweetness`: 단맛
- `saltiness`: 짠맛
- `acidity`: 산미·발효 산미
- `butteriness`: 버터 풍미
- `richness`: 크림·치즈·필링의 진한 정도

### 태그와 목적

- 태그: `WHOLE_GRAIN`, `FERMENTED`, `NUTTY`, `CHOCOLATE`, `FRUIT`, `CHEESE`, `CREAM`, `RED_BEAN`, `HERB`, `SPICY`, `SESAME`, `PLAIN`
- 방문 목적: `QUICK_TAKEOUT`, `BREAD_MEAL`, `DESSERT`, `GIFT`, `CAFE_STAY`, `NEW_DISCOVERY`

값이 없다는 뜻은 `null`이며 0으로 바꾸지 않는다. 특징 신뢰도는 맛의 우수성이 아니라 근거가 그 특징을 지지하는 정도다.

## 9. 대표 매칭 메뉴

매장 안의 활성 메뉴마다 취향 일치 `T`를 계산하고 가장 높은 메뉴를 대표로 선택한다. 동률이면 다음 순서다.

1. 특징 근거 신뢰도 내림차순
2. 마지막 검수 시각 내림차순
3. `menu_id` 오름차순

활성 메뉴 특징이 없으면 유효한 매장 집계 특징으로 추천할 수 있지만 `메뉴 근거 부족` 주의점을 붙인다.

## 10. 내부 관련도와 리뷰 근거

내부 관련도 `R`은 0~1 사이이며 화면에 숫자로 공개하지 않는다.

```text
R = 0.60T + 0.25V + 0.15E
```

- **취향 일치 `T`:** 카테고리 30%, 식감 25%, 맛 20%, 태그 15%, 발효·스타일 10%
- **방문 적합 `V`:** 예산 40%, 확인된 영업 적합 30%, 방문 목적 30%
- **근거 신뢰 `E`:** 특징 신뢰 50%, 출처 다양성 20%, 검수 신선도 20%, 메뉴·가격·영업 완성도 10%

검수된 실제 메뉴 카테고리는 리뷰 추정보다 우선한다. 리뷰 기반 맛·식감·태그는 최근 12개월 안의 서로 다른 유효 리뷰 3개 이상이 지지할 때만 `T`와 `E`에 반영하며 180일 반감기로 최신성을 감쇠한다. 리뷰가 3개 미만인 매장은 후보에서 제거하지 않고 아래 대체 추천을 사용한다. 별점은 `T`, `V`, `E`, `R` 어느 항목에도 넣지 않는다.

0~4 축은 `1 - abs(사용자값 - 특징값) / 4`로 비교한다. 여러 원하는 카테고리는 가장 높은 일치를 사용한다. `avoided`에 일치한 태그·카테고리는 해당 취향 그룹에서 `0.25`를 차감하고 0~1로 제한한다.

사용자가 지정하지 않은 비교 그룹과 후보 특징이 없는 비교는 0.5로 중립 처리한다. 누락 그룹의 가중치를 다른 그룹에 재분배하지 않고 `E`가 낮아지게 한다.

기존 개인 학습 `P`는 제거한다. 즐겨찾기와 피드백은 사용자가 직접 보는 기록과 평가 자료일 뿐, 다른 대화의 순위를 자동으로 바꾸지 않는다.

## 11. 리뷰 부족 대체 추천

최근 12개월의 서로 다른 유효 리뷰가 3개 미만인 매장은 다음 비교 키를 순서대로 사용한다.

1. 강한 제외·영업 상태·최대 거리·하드 예산 통과 여부
2. 검수된 실제 메뉴·카테고리 일치
3. 방문 목적·영업시간·예산 적합
4. 선택한 정렬에 따른 이동시간 또는 직선거리
5. 원장·메뉴·검수 데이터의 최신성과 완성도
6. 전체 평균으로 보정한 별점
7. `store_id` 오름차순

별점의 보정은 리뷰 수가 적은 매장의 극단값이 순위를 지배하지 않도록 전체 평균을 사전값으로 사용하는 결정론적 Bayesian mean으로 계산한다. 별점은 위 1~5번 비교가 모두 같은 경우에만 사용하며, 핵심 메뉴·맛·식감 일치를 역전시킬 수 없다.

대체 추천 결과는 다음 의미의 안내를 표시한다.

> 최근 리뷰 근거가 부족해 확인된 메뉴와 방문 조건을 중심으로 추천했어요.

## 12. 이동시간과 경로 보강

하드 필터를 통과한 후보에는 현재 요청의 정확 출발 좌표 또는 사용자가 선택한 출발지 좌표로 Kakao 경로 API를 호출한다.

- 정확 출발 좌표와 Kakao 원본 응답은 요청 범위를 넘겨 저장하지 않는다.
- 앱 전경에서 100m 이상 이동하거나 사용자가 요청할 때 재계산한다.
- 같은 출발지 버킷·목적지·경로 옵션의 동시에 들어온 요청은 합친다.
- Kakao가 반환한 유효 경로 대안은 목적지별 총 이동시간 오름차순으로 정렬한다.
- 응답이 없거나 쿼터·장애가 발생한 후보는 `ROUTE_UNAVAILABLE`로 표시한다.
- 이동시간을 계산하지 못한 후보에 직선거리 기반 가짜 시간을 만들지 않는다.

경로 호출량이 운영 한도에 닿으면 계산된 후보와 미계산 후보를 명확히 분리한다. 이때 전체 목록을 완전한 이동시간순이라고 표현하지 않고 관련도순 또는 직선거리순 대체 상태로 전환한다.

## 13. 정렬

### 이동시간순 `TRAVEL_TIME`

1. 유효 경로 존재 후보 우선
2. 최단 경로 총 이동시간 오름차순
3. 내부 관련도 `R` 내림차순
4. 근거 신뢰 `E` 내림차순
5. 직선거리 오름차순
6. 마지막 매장 검수 시각 내림차순
7. `store_id` 오름차순

### 관련도순 `RELEVANCE`

1. 내부 관련도 `R` 내림차순
2. 취향 일치 `T` 내림차순
3. 근거 신뢰 `E` 내림차순
4. 유효 경로의 최단 이동시간 오름차순
5. 직선거리 오름차순
6. 마지막 매장 검수 시각 내림차순
7. `store_id` 오름차순

리뷰 부족 매장은 11절의 대체 키를 사용해 동일 정렬 안에 포함한다. 리뷰가 충분하다는 사실만으로 모든 리뷰 부족 매장보다 무조건 앞세우지 않으며, 검수된 메뉴 일치와 하드 방문 조건을 먼저 존중한다.

정렬 방식은 목록의 선두 후보를 실제로 다시 만든다. 지도는 어느 정렬에서도 모든 적격 후보를 표시한다.

## 14. 다양성과 표시 개수

목록의 첫 화면은 상위 5개를 강조하되 아래로 스크롤하면 전체 적격 후보를 볼 수 있다.

상위 5개의 첫 패스에서는 같은 `bakery_id`를 한 번만 허용한다. 5개가 차지 않으면 전체 순위에서 같은 베이커리의 두 번째 매장까지 허용한다. 세 번째 매장은 상위 5개에 넣지 않는다. 실제 후보가 5개 미만이면 범위를 자동 확대하지 않는다.

## 15. 설명 근거

서버는 사용자에게 공개하지 않는 `R`, `T`, `V`, `E`, 대표 메뉴, 기여 항목, 근거 ID와 주의점을 추천 실행에 저장한다. 설명은 다음만 사용한다.

- 가장 큰 양의 기여 최대 2개
- 가장 중요한 데이터 한계 또는 주의점 1개
- 현재 경로의 총 시간·거리처럼 API가 실제 반환한 값

LLM 설명 실패 시 같은 근거로 결정론적 템플릿을 사용한다. 설명 실패는 후보·순위·정렬을 바꾸지 않는다.

## 16. 빈 결과와 완화

단계별 제거 개수를 기록하고 다음 완화만 사용자가 선택하도록 제안한다.

1. 최대 범위를 다음 고정 단계로 확대
2. 예산 하드 조건을 선호로 전환
3. 영업시각 하드 조건 해제
4. 원하는 카테고리를 명시된 인접 카테고리로 확장

강한 제외, 프랜차이즈·폐업·서울 범위와 관리자 차단은 자동 또는 추천 문구로 완화하지 않는다.

## 17. 결정성과 버전

추천 실행은 다음을 기록한다.

- `conversationIntentVersion`
- `recommendationVersion` (`recommendation.v2`)
- `dataSnapshotVersion`
- `featureAggregateVersion`
- `routeProviderVersion`
- `explanationPromptVersion`

부동소수점 반올림 지점을 고정하고 모든 마지막 동점에 자체 ID를 사용한다. 동일 입력·동일 스냅숏·동일 버전·동일 경로 응답이면 바이트 단위로 같은 목록이 나와야 한다.
