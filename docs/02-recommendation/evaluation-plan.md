# 추천 및 MVP 평가 계획

[문서 허브](../README.md) · [PRD](../00-product/prd.md) · [추천 기준](recommendation-spec.md) · [운영 기준](../08-operations/operating-baselines.md)

이 문서는 추천 품질, 결정성, 실패 대체와 5인 사용성 파일럿의 판정 방식을 정의한다. 목표값은 [PRD](../00-product/prd.md), 계산 규칙은 [추천 기준](recommendation-spec.md)을 따른다.

## 1. 평가 질문

1. 사용자가 자연어만으로 첫 추천을 완료할 수 있는가?
2. 강한 제외가 관련도와 상관없이 항상 지켜지는가?
3. 기대한 후보가 상위 5개 안에 포함되는가?
4. 이동시간순과 관련도순이 각 정의대로 동작하는가?
5. 추천 이유와 주의점이 실제 근거와 일치하는가?
6. 위치·LLM·Kakao 장애와 빈 결과에서 과업을 계속할 수 있는가?
7. 과거 대화·삭제·계정 격리가 사용자의 예상과 일치하는가?

## 2. 평가 층

| 층 | 대상 | 실행 시점 | 통과 기준 |
|---|---|---|---|
| 단위 | 축 유사도, 감점, 하드 필터, 정렬, 동점 | 추천 규칙 변경마다 | 전 케이스 통과 |
| 스키마 | 자연어 의도, 설명, 리뷰 특징 JSON | 프롬프트·모델·스키마 변경마다 | 잘못된 출력 저장 0건 |
| 고정 데이터 | 30개 이상 매장·50개 이상 메뉴 | 데이터·추천 버전 변경마다 | 제외 노출 0건, 결정성 100% |
| 대표 시나리오 | 20개 취향·대화 시나리오 | 릴리스 후보마다 | Hit Rate@5 85% 이상 |
| 통합·E2E | 인증, 위치, 대화, 경로, 삭제, 장애 | 릴리스 후보마다 | P0 수용 기준 전부 통과 |
| 사용성 | 비공개 참여자 5명 | P0 기능 완성 후 | 목표 지표 충족 또는 원인 기록 |

## 3. 정답 후보군 작성

개발자와 베이커리에 익숙한 독립 평가자 1명이 각 시나리오의 예상 후보군을 따로 작성한다.

### 허용 근거

- 매장의 공식 메뉴·공식 채널
- 공공 원장 영업 상태와 자체 관리자 검수
- 데이터 설계서의 유효한 메뉴·특징 관측
- 최신성 임계값을 통과한 비식별 집계 근거

### 합의 절차

1. 두 평가자가 상위 후보와 제외 후보를 독립 작성한다.
2. 불일치한 매장만 근거를 함께 확인한다.
3. 근거가 부족하면 정답 후보에 넣지 않고 `INSUFFICIENT_EVIDENCE`로 기록한다.
4. 합의한 후보군, 허용 변형과 이유를 평가 세트 버전에 고정한다.
5. 추천 데이터가 바뀌면 과거 기대값을 조용히 덮지 않고 새 평가 세트를 만든다.

평가자의 개인적 유명세·선호만으로 정답을 만들지 않는다.

## 4. 20개 대표 시나리오 구성

| 그룹 | 개수 | 필수 예 |
|---|---:|---|
| 특정 메뉴 | 4 | 사워도우, 바게트, 베이글, 과일 데니시 |
| 맛·식감 조합 | 4 | 덜 달고 바삭함, 촉촉하고 버터 풍미, 쫄깃함, 발효 산미 |
| 강한 제외 | 4 | 초콜릿 제외, 견과 태그 제외, 특정 매장 제외, 제외 철회 |
| 멀티턴 수정 | 3 | 더 가까운 곳, 카테고리 교체, 관련도순 전환 |
| 방문 조건 | 2 | 현재 위치 30분, 특정 역·예산·시각 |
| 실패·회복 | 3 | 위치 거부, 0개 결과, 경로 또는 LLM 실패 |

각 시나리오는 초기 메시지, 후속 발화, 예상 구조화 상태, 절대 제외, 허용 후보군, 예상 정렬 특성과 데이터 스냅숏을 포함한다.

## 5. 추천 품질 지표

### Hit Rate@5

상위 5개 중 합의된 기대 후보가 하나 이상 있으면 성공이다.

```text
HitRate@5 = 성공한 시나리오 수 / 전체 유효 시나리오 수
목표 >= 0.85
```

데이터에 적격 후보가 없는 시나리오는 임의 성공으로 계산하지 않고 별도의 데이터 공백으로 보고한다.

### 강한 제외 위반

상위 5개뿐 아니라 전체 적격 목록과 지도 마커를 검사한다.

```text
hard_exclusion_violations = 0
```

구조화가 잘못돼 제외가 빠진 경우와 추천 엔진이 제외 후보를 되살린 경우를 별도 원인 코드로 기록한다.

### 결정성

동일 `ConversationIntentV2`, 동일 데이터·추천·경로 응답 버전으로 100회 실행한다.

- 전체 `store_id` 순서 차이 0건
- 대표 메뉴 차이 0건
- 공개 설명 템플릿의 근거 ID 차이 0건

LLM 자연어 표현의 글자 일치는 결정성 지표에 포함하지 않지만 입력 `store_id` 순서와 사실 근거는 같아야 한다.

### 정렬 정확성

- `TRAVEL_TIME`: 유효 최단 이동시간이 오름차순이며 관련도는 동점 키다.
- `RELEVANCE`: 내부 관련도가 내림차순이며 이동시간은 후순위 키다.
- 후보가 충분한 시나리오에서 두 정렬의 선두 5개 또는 순서가 적어도 하나 달라지는지 확인한다.
- 경로가 실패한 후보를 계산된 후보보다 빠르다고 표시하지 않는다.

## 6. 설명 평가

각 추천 카드에 대해 평가자가 1~5점으로 판정한다.

| 축 | 1점 | 5점 |
|---|---|---|
| 관련성 | 입력과 이유가 무관함 | 핵심 메뉴·맛·식감과 직접 연결됨 |
| 근거 충실성 | DB에 없는 사실 포함 | 제공된 근거만 간결히 설명 |
| 한계 투명성 | 오래됨·누락·직선거리 숨김 | 중요한 주의점이 분명함 |
| 선택 도움 | 비교에 쓸 정보 없음 | 시간·거리·이유로 선택 가능 |

관련도·설명 평균 목표는 4.0/5 이상이다. 매장당 이유 2개, 주의점 1개를 넘기지 않는다.

## 7. 5인 사용성 파일럿

### 참여자

- 특정 빵을 찾아본 경험이 있는 비공개 참여자 5명
- 서비스 개발에 직접 참여하지 않은 사람을 우선한다.
- 테스트용 카카오 계정을 따로 요구하지 않고 본인 계정 사용 전에 수집 범위를 안내한다.

### 과업

1. 자연어로 특정 빵을 찾아 첫 결과를 연다.
2. 강한 제외를 추가하고 결과에서 위반이 없는지 확인한다.
3. 이동시간순에서 관련도순으로 바꾸고 차이를 설명한다.
4. 위치 권한을 거부한 상태에서 역·동·구로 추천을 완료한다.
5. 0개 결과를 조건 수정으로 회복한다.
6. 과거 대화를 열어 다른 빵집을 확인한다.
7. 과거 조건으로 새 대화를 만들고 원본과 독립적으로 수정한다.
8. 대화 하나를 삭제하고 다른 기록이 유지되는지 확인한다.

### 측정

| 지표 | 산식 | 목표 |
|---|---|---:|
| 첫 추천 완료율 | 독립적으로 결과를 연 참여자 / 5 | 80% 이상 |
| 입력→결과 중앙값 | 첫 입력 시작부터 결과 로드까지 | 2분 이하 |
| 설명 만족도 | 5점 척도 평균 | 4.0 이상 |
| 장애 대체 완료율 | 성공한 대체 과업 / 시도 | 90% 이상 |
| 빈 결과 회복률 | 회복 성공 / 빈 결과 과업 | 80% 이상 |

관찰자는 사용자가 요청하지 않은 힌트를 먼저 주지 않는다. 막힌 지점, 잘못 이해한 문구와 되돌아간 단계는 이벤트와 관찰 노트로 함께 기록하되 메시지 원문과 정확 위치를 분석 로그에 복제하지 않는다.

## 8. 실패 대체 평가

| 실패 주입 | 기대 결과 |
|---|---|
| 위치 권한 거부 | 5초 안에 직접 출발지 입력 진입, 추천 완료 |
| 위치 권한 철회 | 전경 갱신 중단, 정확 좌표 폐기, 현재 대화 유지 |
| Kakao 지도 실패 | 목록·주소 유지, 지도 재시도 제공 |
| Kakao 경로 실패 | 가짜 시간 없이 관련도·거리 대체, 상세 열기 가능 |
| 의도 분석 스키마 실패 | 한 번 재시도 후 구조화 폼, 메시지 보존 |
| 설명 생성 실패 | 템플릿 이유, 순위 동일 |
| `raw_db` 실패 | 리뷰 작업만 중지, 기존 추천 지속 |
| 원장 30일 초과 | 새 추천 차단, 과거 대화 열람 가능 |
| LLM 비용 상한 | 자동 분석·설명 대체, 결정론적 추천 지속 |

대체 흐름 완료율 목표는 90% 이상이다.

## 9. 보안·개인정보 수용 검사

- 다른 계정의 `conversation_id`, `recommendation_run_id`, `favorite_id` 직접 조회가 403 또는 404다.
- 정확한 좌표가 DB, 애플리케이션 로그, 분석 이벤트, 오류 추적, 대화 메시지 메타와 OpenAI 요청에 없다.
- 카카오 token, provider account ID와 세션 값이 클라이언트 로그에 없다.
- 대화 삭제 후 메시지·상태·추천·연결 피드백이 없다.
- 회원탈퇴 후 사용자 데이터가 없고 Kakao unlink 작업의 비민감 상태만 남을 수 있다.
- `apps/web`의 `raw_db` 접속이 거부된다.

## 11. 릴리스 판정

P0 파일럿 릴리스는 다음을 모두 만족해야 한다.

- 자동 테스트에서 P0 요구사항 수용 기준 통과
- 고정 데이터의 프랜차이즈·폐업·팝업·미검수 노출 0건
- Hit Rate@5 85% 이상
- 강한 제외 위반 0건
- 동일 입력 100회 순위 차이 0건
- 정확 위치·리뷰 평문·비밀 노출 0건
- 위치 거부, LLM·지도·경로 실패, 빈 결과와 비용 상한의 대체 흐름 수동 검수

사용성 목표가 미달이면 숫자를 숨기지 않고 실패 지점과 개선 가설을 기록한다. 품질 지표 미달을 파일럿 참여자의 선호 탓으로 돌리지 않는다.
